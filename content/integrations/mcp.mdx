# MCP Server

Ycode includes an embedded [Model Context Protocol (MCP)](https://modelcontextprotocol.io/) server that lets AI tools build and edit your site. Connect Claude (Desktop, Claude.ai, or Claude Code), ChatGPT, Cursor, or VS Code to your Ycode project and use natural language to create pages, design layouts, manage CMS content, and publish changes.

<Callout type="info" title="Built-in alternative">
For an AI that lives inside the Ycode editor — no external client to install — see the [AI Agent](/docs/editor/ai). It uses the same tool registry as MCP (~130 tools), just wired into the builder's Agent tab instead of an external client. The one difference: the in-app agent can't publish (only you can), while MCP tools can.
</Callout>

## How to Connect

AI tools connect over **OAuth**: you paste one URL into the client, sign in to Ycode, and approve access on a consent screen. Open **Integrations** → **MCP** in the builder to find your **MCP server URL**, per-client setup steps under **How to connect**, and your approved **Connections**.

Ycode supports both OAuth client registration methods clients use today — Dynamic Client Registration and Client ID Metadata Documents — so any client that speaks the MCP Streamable HTTP transport with OAuth can connect.

### Ycode Cloud: one URL for all your sites

On Ycode Cloud, the MCP page leads with a single shared URL:

```
https://mcp.ycode.cloud/mcp
```

Sign in once with your Ycode Cloud account. The connection works on every site you have designer access to — including sites you get access to later. In the conversation, name the site you want to work on and the assistant switches to it with the `list_sites` and `select_site` tools. If you only have one site, it's selected automatically.

In Claude, search the connector directory for **Ycode** and click **Connect**. If Ycode isn't in your directory yet, add it as a custom connector with the URL above. Each site's own URL (`https://your-site.com/ycode/mcp`) remains available on the same page as a secondary option.

If you start connecting while logged out, Ycode sends you back to the consent screen after you sign in, so the connection request isn't lost.

### Self-hosted: one URL per project

Self-hosted projects aren't listed in the Claude or ChatGPT connector directories, because every project has its own URL. Add your project as a **custom connector** instead, using the **MCP server URL** from **Integrations** → **MCP** — it looks like `https://your-site.com/ycode/mcp`.

Clients like Claude.ai and ChatGPT connect from the vendor's servers, so they need a public HTTPS URL and can't reach `localhost`. For local development, use Cursor, Claude Code, or VS Code. If your project is served from several hostnames or behind a reverse proxy, set [`NEXT_PUBLIC_MCP_SERVER_URL`](/docs/getting-started/configuration#environment-variables) to the public URL clients should use.

## Client Setup

The **How to connect** tabs on the MCP page show these steps with your URL filled in.

**Claude Desktop and Claude.ai** — Open **Settings → Connectors**, scroll past the directory, and click **Add custom connector**. Name it "Ycode", paste the MCP server URL into **Remote MCP server URL**, and leave the OAuth client ID and secret fields empty. Click **Add**, then **Connect**, and sign in to Ycode to approve access. Custom connectors require a paid Claude plan (Pro, Max, Team, or Enterprise); on Team and Enterprise an owner may need to add the connector for the organization.

**Claude Code** — Run the command below, then run `/mcp` in Claude Code and choose `ycode` to sign in:

```bash
claude mcp add --transport http ycode https://your-site.com/ycode/mcp
```

**Cursor** — Open **Settings → MCP** and click **Add new MCP server**, or edit `.cursor/mcp.json` directly:

```json
{
  "mcpServers": {
    "ycode": { "url": "https://your-site.com/ycode/mcp" }
  }
}
```

**ChatGPT** — Open **Settings → Connectors** and enable **Developer mode** (under Advanced). Click **Create**, name it "Ycode", and paste the MCP server URL. Choose **OAuth** authentication, then sign in to Ycode and approve access. Developer mode connectors are available on ChatGPT Plus, Pro, Business, Enterprise, and Edu plans.

**VS Code** — Run the command below, then open the Chat view, click the tools icon, and start the `ycode` server to sign in:

```bash
code --add-mcp '{"name":"ycode","type":"http","url":"https://your-site.com/ycode/mcp"}'
```

### Approving Access

Ycode shows a consent screen with your site name and the client requesting access. If the client redirects to an app on your own machine (Claude Code, Cursor), the screen warns you that the target is a local application. Approve to connect.

Access tokens last 1 hour. Refresh tokens last 30 days, rotate on every use, and are bound to the client that received them, so a connected client stays signed in until you revoke it.

### Tool Permissions

The first time the assistant uses a tool, the client asks for your permission. Choose **Always allow** for the editing tools — every change is a draft until you publish — and keep **Publish** and the delete tools on ask. On the Cloud shared URL, one approval covers all your sites.

Every tool reports a title and a read-only or destructive hint, which clients use to decide which calls need confirmation. Editing tools batch a whole turn of changes into one `batch_operations` call, so a page edit usually needs one approval instead of one per layer.

<Callout type="info" title="Live sync">
Changes made through the MCP server appear in the browser editor in real time via Supabase Realtime. You can watch the AI build your site as it works.
</Callout>

## Start Building

However you connected, ask the AI to create pages, add elements, style them, manage CMS content, and publish. Tool calls happen in your project; changes appear in the editor live.

## What AI Agents Can Do

The MCP server is at version **1.0**, with full feature parity with the Ycode editor. Tools are organized by area:

### Pages

Create, update, duplicate, and delete pages. Manage page settings including SEO metadata, custom code injection, and password protection. Organize pages into folders. Mark pages as the homepage (`is_index`), as a dynamic page (`is_dynamic`), or as an error page (`401`, `404`, `500`). Bind dynamic pages to a CMS collection with a slug field and control how `next-item` / `previous-item` link keywords traverse the collection.

Pages also support draft state via `is_publishable` — set `false` on `create_page` / `update_page` to keep a page out of the live site while leaving it editable in the builder. Pages with `is_publishable: false` are skipped on publish.

### Layers and Elements

Add any element type — including tables (`table`, `thead`, `tbody`, `tr`, `td`, `th`). Update design properties (layout, typography, spacing, sizing, backgrounds, borders, effects, position, transforms, transitions), text content, images, links, videos, and background images.

Design tools accept a `ui_state` argument (`hover`, `focus`, `active`, `disabled`, `current`) so the same property can take different values per state. The `current` state activates when a link points to the page being viewed, which is how you style the active item in a navigation menu.

Layer settings cover the full surface: sliders (pagination, easing, touch events, slides per group), CMS-bound lightboxes (multi-image fields, groups), maps (Mapbox / Google Maps with coordinates, zoom, marker color, navigation controls), CMS-bound select/radio/checkbox options, plus per-layer `hidden`, `keepInHtml`, `filter_on_change`, and placeholder flags.

The design schema reaches further than the visual controls in the editor sidebar. Agents can also set `mixBlendMode` (multiply, screen, overlay, and the rest), raw `filter` and `backdropFilter` values, and any CSS `backgroundImage` — including inline SVG data URIs for noise and texture overlays. For the rare property with no design field at all (such as `pointer-events`), agents can set a `style` custom attribute on the layer via `update_layer_settings`. Combined with absolute positioning and z-index, this is enough to build tinted scrims, film-grain overlays, and similar effects as native layers instead of HTML embeds.

Links support URLs, internal pages, email, phone, anchors (`anchor_layer_id`), specific dynamic items (`collection_item_id`), assets, plus `rel` and `download` attributes.

`batch_operations` covers the same edits as the single tools — including `update_link`, `update_settings`, and `update_background_image` ops — so an agent can apply a whole turn of changes in one call. `update_component_layers` accepts `update_link` and `update_settings` ops too, preserving any linked component variable.

Move, reorder, and delete layers.

### Layouts

Insert pre-built layout templates — hero sections, headers, feature grids, footers, and more. Layouts provide a quick starting point that the AI can then customize.

### CMS

Create and manage collections, fields, items, and item values. Field types include text, rich text, number, boolean, date, asset (image / audio / video / document, with optional `multiple`), reference, `option` (with custom choices), and `count` (computed from a referenced collection).

Add per-field metadata (`default`, `fillable`, `hidden`, `is_computed`), set a default `sorting` on each collection (`field`, `direction`), reorder fields with `reorder_collection_fields`, and reposition manually-sorted items with `set_collection_item_order`.

### Dynamic Content (Collection Lists, Bindings, Visibility)

Bind layers to CMS data without leaving the agent:

- `bind_collection_layer` turns a layer into a Collection List bound to a collection, with sorting, limit, pagination (Pages or Load More), and **nested-collection sourcing** from a reference, multi-reference, multi-asset, or inverse-reference field — useful for "show this category's products" or "show this post's tags" patterns.
- `set_collection_filters` writes filter rules as AND-of-OR condition groups. Conditions can compare a field to a static value, to a **visitor-facing filter input** (`input_layer_id`), or to the **current page's item** on dynamic pages (the "Current Tag" / "Current Category" pattern). Item ID conditions support both selected items and the current page item.
- `set_layer_visibility` writes show/hide rules for any layer with the same condition model (`field`, `item_id`, and `page_collection` count sources).
- `bind_layer_field` binds dynamic content onto a layer: text and rich-text values, image `src` / `alt`, video `src` / `poster`, audio `src`, and background images. Pass an optional `prefix` / `suffix` for inline formatting.
- `set_dynamic_text` composes one text node from an ordered list of literal strings and field references — useful for "Posted on `{Date}` by `{Author}`" patterns.

### Components

Create reusable components with variables, edit component layer trees, and manage the component library. Variables include `rich_text`, `variant`, `visibility`, and `id` types, plus `placeholder` and `default_value` fallbacks.

A `visibility` variable is a boolean (`{ visible: true|false }`) linked to a layer's Settings `Visibility`. Instances override it with `visible` on `set_component_instance`. Nested pass-through works the same as other variable types. Deleting the variable unlinks layers and clears overrides.

An `id` variable is a string (`{ id: "…" }`) linked to a layer's Settings `ID`. Instances override it with `element_id` on `set_component_instance`. Values are sanitized to a valid HTML id. Unlinking or deleting the variable falls back to the layer's static id.

Variants have full CRUD: `list_component_variants`, `create_component_variant` (optionally cloning an existing variant), `update_component_variant`, and `delete_component_variant`. `update_component_layers` accepts an optional `variant_id` so edits target a specific variant without clobbering the others.

### Animations and Interactions

Add animations from 18 curated presets — reveal, hover, click, parallax, stagger, and loop families — in a single tool call:

- `add_animation` — apply a preset to one or more `targets`
- `list_layer_animations`, `remove_layer_animation`, `clear_layer_animations`
- `set_layer_interactions` — raw escape hatch for custom GSAP timelines

A dedicated **Animation Presets Reference** resource documents every preset, trigger semantics, and the raw interaction shape.

### Site Settings

Read and update project settings (site name, description, custom CSS, and more). Manage URL redirects with `list_redirects`, `add_redirect`, `update_redirect`, and `delete_redirect` — including regex patterns and `301` / `302` types.

### Forms

View form submissions, update statuses, and manage form data. `update_form_settings` configures success behaviour (`message` or `redirect` to a URL) and email notifications (`to`, `subject`).

### Localization

Manage locales and translations for multilingual sites. Start with `list_translatable_content` to discover exactly what can be translated for a page, component, or CMS item — the response returns the precise `source_type`, `source_id`, `content_key`, and `content_type` for every translatable string, plus the current source value (and any existing translation when a locale is passed). Use `set_translation` for plain-text values, `set_rich_text_translation` for rich-text fields (it accepts structured blocks and writes a properly-formed translation — no need to hand-assemble the underlying document JSON), or `batch_set_translations` for bulk updates.

For large or multi-language jobs, keep discovery and writes lean. Pass `untranslated_only: true` (and a `locale_id`) to `list_translatable_content` so it returns only keys still missing a completed translation — the cheapest way to resume work or add a locale. Paginate big CMS collections with `limit` and `offset` instead of loading everything at once. `list_translations` accepts `source_type` and `completed` filters when you need a subset of existing rows.

`batch_set_translations` accepts up to 1000 items per call. Set a top-level `locale_id` once and omit it on each item — do not repeat the locale on every row. Prefer one large batch over many small `set_translation` calls. Rich text in a batch uses `content_type` `richtext` with a JSON-stringified Tiptap document; use `set_rich_text_translation` only when you are writing a single field.

Page custom code (the head and body snippets) is translatable too: it comes back from `list_translatable_content` with `content_type` `code`, and `set_translation` and `batch_set_translations` accept the same type.

Translations default to **completed** so they appear on the live site after publishing — pass `is_completed: false` only for work-in-progress drafts. Rich-text payloads are validated against their declared `content_type` and rejected with an actionable error rather than silently stored as unrenderable data. `get_unpublished_changes` reports pending translation and locale counts alongside other unpublished changes, so agents know when there's something to publish.

### Styles

Create, apply, update, and delete reusable layer styles for consistent design across the site. Use `set_layer_styles` to stack multiple styles on a single layer in priority order — the same combo-class model the editor uses, where later styles in the stack win on conflicting properties.

### Assets

Upload images and files (from URL or base64), list and organize assets in folders.

### Color Variables

Create, update, delete, and reorder global color variables.

### Fonts

List installed fonts, search Google Fonts, and add new fonts to the project.

### Export

`export_layer_html` renders any layer subtree to a self-contained HTML string with Tailwind classes preserved — useful for handing a finished section off to another tool or saving it as a snippet.

### Publishing

Check for unpublished changes and publish all drafts to make the site live.

## Managing Connections

The **Connections** section on the **Integrations → MCP** page lists every approved AI tool. Each row shows `Connected` (or `Expired` once its refresh token lapses), the date it connected, and when it was last used. Open a row's menu and choose **Revoke connection** to cut the client off — it has to reconnect and approve access again.

On Ycode Cloud, connections made through the shared URL are listed there too and can be revoked from any of your sites.

### Legacy URL Tokens

For clients that don't support OAuth, expand **Legacy URL tokens** at the bottom of the page and click **Generate URL token**. Give it a **Connection name** (for example `Windsurf`) and copy the URL shown in **Your MCP URL** — it embeds the token (`https://your-site.com/ycode/mcp/ymc_...`).

URL tokens never expire until you delete them, and anyone with the URL can access the project. Prefer the OAuth URL whenever your client supports it, and treat URL tokens like API keys.
